## Decisions
- **Auth for the route:** the client uses supabase-js with localStorage sessions (no cookies), so it sends `Authorization: Bearer <access_token>`. Server calls `admin.auth.getUser(token)` (verifies the JWT with Supabase Auth), then `admin.auth.admin.deleteUser(data.user.id)`. The id never comes from the body; the body is ignored. Reason for Route Handler over Server Action: bearer-token fits the existing client-side session.
- **Fail closed:** if `SUPABASE_SERVICE_ROLE_KEY` or `NEXT_PUBLIC_SUPABASE_URL` is unset, returns 503 `Account deletion is unavailable.` and logs the real reason server-side. Checked locally (production build, env unset): 503.
- **Origin check:** if an `Origin` header is present and differs from the request origin, 403. Extra guard; bearer auth already blocks cross-site cookie attacks.
- **Generic errors:** responses are only `{error: "<short generic>"}` (401/403/500/503). Details go to `console.error` only.
- **Service-role client:** created per request with `persistSession:false`, only inside the route file. No client import path to it.
- **UI:** Delete button reveals a confirm box; the final button is disabled until input is exactly `DELETE`. On success: sign out, remove local keys `opq-v1`, `opq-stats`, `opq-opts`, `opq-seen`, reload page. On error: shows the server's generic message.
- **CSP:** no change needed (same-origin `connect-src 'self'`).
- **CI:** Node 22, `permissions: contents: read`, actions pinned to major tags (not SHAs). Dummy `NEXT_PUBLIC_*` env for build. Runs on push to main and on PRs. Lint script exists (`eslint`), so it is included.
- **SPEC ticks:** only items read in code. Notes in SPEC say what was and was not checked.
- Local `npm ci` was needed in the worktree (no node_modules); `node_modules` is gitignored.
